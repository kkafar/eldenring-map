# Elden Ring Map

Personal web app for tracking Elden Ring playthroughs on an interactive map: markers for
locations / items / enemies, per-profile discovered/collected state, notes, filters, search.
Single user on localhost for now; data model and API are designed to grow to multi-user and
remote deployment later.

## Read first

- Product brief and requirements: `local.notes/goals.md` (gitignored, exists only on this machine)

## Layout

pnpm workspace with two packages:

- `packages/client`: Vite 7 + React 19 + TanStack Router (file routes) + TanStack Query + tRPC client
  + Tailwind 4 with hand-rolled Material 3 tokens in `src/styles/`.
- `packages/server`: Node + Hono + tRPC + Drizzle ORM + better-sqlite3 (`src/`). Schema in `src/db/schema.ts`,
  generated migrations in `drizzle/` (run `pnpm --filter server db:generate` after a schema change; they are
  applied at boot). The source-data taxonomy is `src/lib/taxonomy.ts`. The client imports only
  `type AppRouter` from it via the `server` workspace dependency.
- `scripts/`: Python helpers. `scrape.py` produced the marker data, `tileimg.py` cuts map tiles.

## Data (not in git)

- Marker data: `packages/client/src/data/items.json`, 3,131 records in 22 source categories.
  Coordinates are strings in the source map's Leaflet `CRS.Simple` lat/lng: `x` is lat (north–south,
  more negative = further south), `y` is lng (west–east). They are not image pixels; a calibration
  step maps them (plan, section 4.3).
- Images: `packages/client/src/assets/` (811 MB). The useful parts are
  `m0-overworld-tiled/{z}/{y}/{x}.jpg` (256 px JPEG pyramid, z0–z6, z6 = native 9728×9216,
  libvips `dzsave --layout google`), `maps/m0-overworld.png` and `maps/m1-underground.png`
  (9728×9216 sources), and `icons/` (103 game icons). Everything else there is a redundant re-cut.
- Server copies (populated by `pnpm --filter server import:assets`, both gitignored):
  `packages/server/storage/` (tiles/<mapId>, tiles/blank.png, maps, icons, main.db3; later uploads) and
  `packages/server/seed/markers/` (items.json, categories.json, source.json with the wiki base URL used to
  absolutize links). The server serves from `storage/`. `pnpm --filter server tiles:generate <mapId> <png>`
  re-cuts a pyramid with libvips (black padding); the overworld one in `storage/` was generated this way.
- `pnpm --filter server import:markers [--dry-run] [--overwrite]` imports the seed JSON into the db
  (idempotent; existing rows are kept unless `--overwrite`). Calibration constants: `seed/calibration.overworld.json`.
- Canonical marker coordinates inside the app: native pixels of the full-resolution map, y down.
- Uploaded marker images: `packages/server/storage/uploads/<sha256-prefix>.<ext>`, served at `/uploads/`.

## App structure

- Client routes: `/` → `/map/overworld`; `/map/$mapId?marker=ID` (map + side panel with Markers and
  Details tabs, placement mode for new markers); `/categories`; `/profiles`.
- Map layer: `packages/client/src/components/map/` (pixel CRS, canvas marker layer with a spatial index,
  icon cache). In dev, `window.__eldenMap = { map, layer }` is exposed for profiling.
- Server routers: maps, categories (+ `icons` query), markers, profiles, progress, notes; plain routes for
  tiles, icons, uploads (`POST /api/upload`) and, in production, the built client.

## Commands

- `pnpm dev` runs both packages: Vite on :3000 (proxies `/api`, `/tiles`, `/icons`, `/uploads` to the
  server) and the Hono server on :8088. tRPC is mounted at `/api/trpc`; `/api/health` is a liveness check.
- `pnpm typecheck`, `pnpm lint` (ESLint flat config at the root), `pnpm format` (Prettier defaults),
  `pnpm test` (vitest in the server), `pnpm build`, `pnpm start` (production: the server serves the built client).
- `packages/client/src/routeTree.gen.ts` is generated by Vite (dev or build) and gitignored; run `pnpm dev`
  or `pnpm --filter client build` once after a fresh clone before `pnpm typecheck`.

## Working conventions

- Research the repo with subagents and keep only their conclusions in the main context.
- Keep changes surgical and minimal; no speculative abstractions or unrequested features.
- Run Prettier only on files you touched (`pnpm exec prettier --write <files>`); pre-existing files such as
  `packages/client/src/styles/*.css` are not Prettier-formatted and must not be reformatted in passing.
- Never name the wiki the marker data came from in docs, code or identifiers; say "source data" / "seed".
